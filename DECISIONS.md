# Architecture Decision Records (ADRs)

## ADR 001: JSON Domain-Specific Language (DSL) with Schema Versioning

### Context
Strategies must be created visually, generated by LLMs, audited via CLI, and shared across environments[cite: 1, 2]. Generating raw Python source code creates security risks, prevents static validation, and makes schema evolution impossible[cite: 1].

### Decision
Serialize all strategies into declarative JSON AST trees with top-level `schema_version` pinning (e.g., `"schema_version": "1.0"`)[cite: 1]. The `strategy_compiler` parses these trees into stateless execution objects[cite: 1].

### Consequences
- **Positive**: Strict decoupling, safe serialization, and clean forwards/backwards compatibility as strategy structures evolve[cite: 1].
- **Negative**: Requires writing migration scripts when incrementing DSL versions[cite: 1].

## ADR 002: Air-Gapped Local Paper Trading Engine

### Context
The system is built for quantitative research and live forward-testing under Indian market conditions without risking live capital[cite: 1, 2].

### Decision
Exclude live broker order placement code entirely[cite: 1, 2]. All execution routes strictly through `core/PaperBroker`, updating an immutable local ledger[cite: 1, 2].

### Consequences
- **Positive**: Absolute capital safety; auditable, deterministic simulation logs[cite: 1, 2].
- **Negative**: Exchange queue position cannot be perfectly modeled (mitigated by conservative slippage and spread penalties)[cite: 2].

## ADR 003: Plotly Dash for Quant Research vs. Flutter Frontend

### Context
The platform requires dense, low-latency options chain grids, real-time interactive Greeks modeling, and dynamic payoff diagrams that recompute on every keystroke[cite: 2]. A standalone Flutter mobile/TV app was considered, but building a separate client app creates cross-language API maintenance overhead during early quantitative development.

### Decision
Standardize on **Plotly Dash** (multi-page, `dash.register_page`) for the primary v1 Research Workstation[cite: 2]. Retain a decoupled service layer so a Flutter mobile/TV client can be integrated via REST/WebSocket APIs in a future milestone without rewriting trading logic[cite: 2].

### Consequences
- **Positive**: Direct Python integration with NumPy, Polars, and Black-Scholes engines; fine-grained callback-based UI updates without full-page reloads[cite: 2].
- **Negative**: Dash is optimized for desktop browsers, making mobile/TV touch or D-pad interfaces impractical in this phase.

## ADR 004: Validation Engine Policy Profiles ("Institutional" as Strict Default)

### Context
Options trading carries extreme tail risk and gamma traps (e.g., deep OTM naked selling near expiry)[cite: 1]. Hardcoded validation thresholds limit flexibility for different trading styles[cite: 1].

### Decision
Implement configurable validation policies where `Institutional` serves as the strict, non-negotiable default (enforcing positive mathematical expectancy, strict drawdown caps, and gamma limits), alongside configurable alternative tiers (e.g., `Beginner`, `Moderate`)[cite: 1].

### Consequences
- **Positive**: Prevents catastrophic LLM hallucinations from reaching the paper ledger while keeping the validation engine modular and reusable[cite: 1].
- **Negative**: High win-rate setups that rely on negative mathematical expectancy will be blocked under the default policy[cite: 1].

## ADR 005: Generic ForecastEngine & Broker Interfaces

### Context
Direct coupling to vendor SDKs (Kotak Neo) or foundation model repositories (Kronos) leads to vendor lock-in and brittle maintenance when APIs or libraries change[cite: 1, 2].

### Decision
Wrap all external market data behind abstract broker adapters and all predictive AI models behind a generic `ForecastEngine` interface[cite: 1, 2]. Upstream consumers interact only with standardized `Bar`, `ChainRow`, and `ForecastResult` entities[cite: 1, 2].

### Consequences
- **Positive**: Seamless model replacement (e.g., swapping Kronos for Chronos, or Kotak for Zerodha/Dhan) with zero core engine code changes[cite: 1, 2].
- **Negative**: Requires maintaining data normalization and unit test fixtures for each adapter layer[cite: 1, 2].

## ADR 006: Hybrid Local SQLite + Dockerized Infrastructure Option

### Context
Local Fedora developers need lightweight zero-setup execution, but multi-day tick ingestion, background model training, and timeseries caching quickly outgrow single-file SQLite deployments[cite: 2].

### Decision
Support local standalone development with SQLite and Parquet by default, but provide an optional `docker-compose.yml` defining PostgreSQL (relational state) and Redis (pub/sub market data cache)[cite: 2].

### Consequences
- **Positive**: Frictionless local onboarding with an immediate path to robust multi-service scaling.
- **Negative**: Requires maintaining both SQLite and PostgreSQL dialects via Alembic migrations.

## ADR 007: Strict Prohibition of Dynamic Code Execution in Strategy Builder

### Context
Strategies must be created visually via Plotly Dash, generated by LLMs (Suggestor), audited via CLI, and shared across environments. Allowing inline Python evaluation or "Sandboxed Python" condition evaluators introduces severe remote code execution vulnerabilities, escapes, non-deterministic runtime behavior, and breaks cross-platform serialization.

### Decision
Strictly prohibit dynamic code execution (`eval()`, `exec()`, compile-time Python code generation, and sandboxed Python runners). All strategy logic must be expressed exclusively as declarative JSON AST trees with a closed, registered set of statically typed operators (e.g., `GREATER_THAN`, `LESS_THAN`, `CROSSES_ABOVE`, `CROSSES_BELOW`, `WITHIN_RANGE`, `AND`, `OR`). Complex indicator calculations and custom signals must be implemented as statically compiled, unit-tested Python classes registered in the indicator catalog, never interpreted dynamically at runtime.

### Consequences
- **Positive**: Absolute immunity from arbitrary code execution attacks; guarantees full JSON schema validation, deterministic replay, and safe persistence.
- **Negative**: Users and LLMs cannot inject ad-hoc Python scripts; new indicator primitives must be registered as statically defined components.

## ADR 008: Concurrency & State Decoupling (WAL SQLite + In-Memory Ring Buffer)

### Context
The system ingests high-frequency WebSocket ticks (hundreds of ticks per second for active option strikes) while the Plotly Dash UI polls runtime state every few hundred milliseconds via `dcc.Interval`. Concurrent writes from the ingestion pipeline and reads from the UI against a default SQLite file will cause database lock contention (`sqlite3.OperationalError: database is locked`).

### Decision
Adopt a bifurcated state storage architecture:
1. High-frequency tick updates and real-time candle aggregations are maintained in an in-memory thread-safe ring buffer (and Polars DataFrame cache). Dash UI callbacks read real-time quotes directly from this in-memory cache.
2. Relational domain entities (`Order`, `Trade`, `Position`, `AccountBalance`, `Strategy`, `Run`, `ValidationResult`) are persisted in SQLite with Write-Ahead Logging enabled (`PRAGMA journal_mode=WAL; PRAGMA busy_timeout=5000;`).
3. Multi-day tick and bar histories are periodically flushed and partitioned into Parquet files under `data/cache/`.

### Consequences
- **Positive**: Eliminates SQLite database lock contention; enables sub-millisecond UI updates; supports zero-dependency local execution without forcing a mandatory external Redis container.
- **Negative**: In-memory live tick buffer is ephemeral and resets if the background ingestion process halts (all transactional ledger entries remain durable in SQLite).

## ADR 009: Dynamic Instrument Expiry Discovery from Broker Scrip Master

### Context
Hardcoding contract expiry days (such as assuming every Thursday at 15:30 IST) introduces settlement bugs in Indian derivatives markets, where expiry schedules vary across indices (e.g., FINNIFTY on Tuesdays, BANKNIFTY previously on Wednesdays, NIFTY on Thursdays) and change according to SEBI regulatory circulars.

### Decision
Prohibit hardcoding days of the week or static calendar rules for options expiries and physical settlement cutoffs. All expiration timestamps, strike intervals, and lot sizes must be discovered and resolved dynamically at runtime from the active broker Scrip Master metadata feed (`contract_master`).

### Consequences
- **Positive**: Completely resilient against exchange regulatory calendar revisions across all current and future underlyings (NIFTY, BANKNIFTY, FINNIFTY, MIDCPNIFTY, SENSEX).
- **Negative**: Backtest and historical replay fixtures must bundle valid contract master metadata records alongside historical OHLCV candles.

## ADR 010: Simulation Integrity, Portfolio Net Equity Accounting & Timeframe Annualization

### Context
Adversarial red-team testing of Phase 5 revealed critical simulation realism vulnerabilities:
1. **Portfolio Equity Accounting Inflation**: `PaperBroker` previously calculated `total_capital = cash + used_margin + unrealized_pnl`. For short positions, turnover proceeds were added to cash while `used_margin` was also added to total capital, creating phantom capital out of thin air. For long positions, `used_margin` was marked to market, double-counting unrealized profit.
2. **Position Reversal Circuit Breaker Bypass**: In `RiskEngine`, any sell order against a long position was flagged as a closing order (`is_closing = True`) without inspecting quantity. A trader could issue a massive reversal order (e.g., SELL 100 when Long 10) during a circuit breaker trip and open a large 90-short position, bypassing pre-trade gates.
3. **Static Sharpe Annualization**: The performance engine defaulted to 252 periods/year for all strategies, distorting Sharpe/Sortino ratios for intraday 1m or 5m timeframes.
4. **Options Execution Assumptions**: Multi-leg options DSL execution against underlying cash candle prices fails to model non-linear derivative Greeks, IV smile skew, and strike liquidity.

### Decision
1. **Net Portfolio Market Value Accounting**:
   In `PaperBroker`, `portfolio_market_value = sum(pos.qty * ltp)`. Equity is strictly defined as `total_capital = cash_balance + portfolio_market_value`. Long positions (`pos.qty > 0`) add positive value; short positions (`pos.qty < 0`) introduce negative liability offsetting short sale proceeds.
2. **Position Reversal Partitioning**:
   In `RiskEngine.validate_order`, strictly distinguish pure closing orders (`order.qty <= abs(existing_qty)`) from position reversals (`order.qty > abs(existing_qty)`). Reversal excess (`net_new_qty = order.qty - abs(existing_qty)`) is treated as a new directional order and must pass drawdown circuit breaker, net margin utilization (factoring in released margin), and lot limit gates.
3. **Timeframe-Aware Annualization Factor**:
   Implement `resolve_periods_per_year` based on the 375-minute NSE regular trading session (09:15 to 15:30 IST): 1d = 252, 1h = 1,575, 15m = 6,300, 5m = 18,900, 1m = 94,500. `BacktestConfig.periods_per_year` defaults to `None`, dynamically resolving from the strategy DSL timeframe.
4. **Options Backtesting Boundary Placeholder**:
   Establish `OptionsBacktestRunner` in `aditrader/backtesting/options.py` as an explicit architectural placeholder raising `NotImplementedError`, preventing premature claims of derivative options backtesting until option chain tick feeds and synthetic IV surface modeling are implemented in Phase 7/8.

### Consequences
- **Positive**: Eliminates phantom equity inflation; guarantees 100% mathematical consistency in equity tracking; prevents circuit breaker and margin limit evasion on position flips; ensures accurate risk-adjusted performance metrics across intraday timeframes.
- **Negative**: Backtest results for high-frequency intraday strategies will reflect accurate (often lower) annualized Sharpe ratios compared to uncalibrated daily scaling.

## ADR 011: Research Integrity Hardening (Options Air-Gap, Volume Realism, Session Risk & Finite Metrics)

### Context
Hostile adversarial review (Phase 5.5.1) identified remaining structural simulation realism and statistical metric distortions:
1. **Silent Options Proxy Execution**: Strategy DSL definitions containing multi-leg options could be passed to `BacktestRunner` and executed against underlying cash/futures OHLCV candles, generating deceptive results without error.
2. **Infinite Liquidity Assumption**: Backtests assumed 100% order fill regardless of bar trading volume, allowing large positions to fill against illiquid candles.
3. **Session Boundary Risk Blindness**: `RiskEngine`'s intraday drawdown circuit breaker evaluated all-time peak equity without resetting on session/date boundaries, causing multi-day backtests to remain locked out after an initial day's drawdown or misinterpreting intraday risk.
4. **Terminal Position Accounting Distortions**: Open positions remaining at backtest terminus were either omitted from terminal equity or liquidated via fake injected trades that polluted trade counts, win rates, and expectancy.
5. **Infinite Statistical Metrics**: Zero downside volatility (Sortino) and zero gross losses (Profit Factor) returned `float('inf')`, distorting optimizer objective functions and breaking serialization.
6. **Quantity vs. Lot Conflation**: Derivative contracts (e.g., NIFTY 25 shares/lot, RELIANCE 250 shares/lot) were evaluated as raw unit counts against `max_concurrent_lots`, prematurely rejecting standard lot orders.

### Decision
1. **Strict Options Simulation Air-Gap Guard**:
   In `BacktestRunner.run`, inspect `strategy.dsl.legs`. If non-empty (`len(strategy.dsl.legs) > 0`), immediately raise `UnsupportedStrategyError`. Proxy execution of multi-leg option strategies on spot candle data is strictly prohibited until dedicated option-chain simulation is ready.
2. **Volume Participation & Liquidity Constraint**:
   Add `max_volume_participation_pct` (float, e.g. 0.10) and `volume_limit_action` (`Literal["REJECT", "PARTIAL_FILL"]`) to `BacktestConfig`. When order quantity exceeds the allowed participation of the current bar volume, the engine deterministically rejects or clamps the order according to policy.
3. **Intraday Session Boundary Reset**:
   In `BacktestRunner.run`, track session date transitions. When a new date is encountered, invoke `risk_engine.on_session_start(bar.timestamp, current_equity)` to reset session peak equity and clear the intraday circuit breaker while preserving cumulative portfolio equity curve.
4. **Terminal Open-Position Accounting**:
   Add `terminal_positions`, `terminal_unrealized_pnl`, and `liquidated_ending_equity` to `BacktestResult`. Evaluate unrealized mark-to-market and compute hypothetical liquidation equity including full slippage and statutory costs. Never inject synthetic trades into roundtrip trade performance metrics.
5. **Finite & Statistically Undefined Metric Representation**:
   Return `None` (typed `float | None`) instead of `float('inf')` for undefined statistical states (zero downside variance in Sortino, zero losses in Profit Factor, zero return variance or $N < 2$ in Sharpe/SQN).
6. **Derivative Contract Lot Semantics**:
   Add `lot_sizes` registry and `resolve_lots(symbol, qty, default_lot_size)` to `RiskEngine`. Pre-trade Gate 4 evaluates integer lot counts (`ceil(qty / lot_size)`) rather than raw share quantities.

### Consequences
- **Positive**: Guarantees zero look-ahead and proxy leakage for options; enforces realistic liquidity limits; enables multi-day intraday risk management; prevents statistical metric crashes; preserves pristine roundtrip trade records.
- **Negative**: Multi-leg option strategies cannot be executed by `BacktestRunner` (must await dedicated option-chain runner in future milestones); strategies with zero losses report `profit_factor = None` instead of `inf`.
